Context Restorer for Freshservice
Developed by Leo Naloufi

Purpose

Context Restorer for Freshservice preserves browser navigation context when Freshservice/Freshworks reauthentication returns the user to a generic home page or dashboard instead of the page used before session expiration.

The extension does not alter authentication, extend session duration, bypass security controls, or access identity-provider credentials.

Permissions

webNavigation

This permission is used to receive top-level HTTPS navigation events so the extension can:

  • detect compatible Freshservice portals;
  • identify FreshID logout and login transitions;
  • remember useful Freshservice navigation context;
  • detect the return to Freshservice after authentication;
  • restore the previously used Freshservice page when necessary.

Navigation information used by the extension is not transmitted to the developer or to any external server.

storage

chrome.storage.session is used for temporary browser-session information such as:

  • per-tab Freshservice URL context;
  • temporary portal detection context;
  • authentication and restoration state;
  • restoration timestamps and status;
  • a small local debug log containing only extension events.

chrome.storage.local is used for persistent extension configuration and non-content statistics such as:

  • detected or manually added Freshservice portal origins and hostnames;
  • enabled or disabled portal state;
  • portal detection source and timestamps;
  • restoration counters;
  • timestamp and origin of the latest successful restoration.

Full Freshservice ticket or page paths are not persisted to chrome.storage.local.

Data handled by the extension

The extension processes Freshservice portal hostnames and Freshservice page URLs required to provide navigation restoration. This information remains in the local browser storage described above.

Data the extension does not access

  • cookies;
  • passwords;
  • form contents;
  • Freshservice ticket contents;
  • request or response bodies;
  • Entra ID, SAML, OAuth or Freshworks tokens;
  • identity-provider credentials.

Network and data sharing

The extension performs no external network request of its own.

No extension data is sold, transferred, synchronized to an external service, shared with advertisers, or used for creditworthiness or lending purposes.

When restoration is required, the extension uses the browser extension API to navigate the current tab back to a Freshservice URL that was already observed in that same browser context.

Automatic portal detection

Standard *.freshservice.com portals can be recognized by hostname. Custom domains are confirmed through Freshservice-specific route signatures or FreshID authentication behavior. Before confirmation, a possible application URL may be held temporarily in session memory for the current tab so it can be recovered if the same origin subsequently confirms itself as Freshservice.

Retention

Session-specific page context is temporary and is kept in browser session storage. Persistent storage is limited to configured/detected portal identifiers and restoration statistics required for extension operation.
